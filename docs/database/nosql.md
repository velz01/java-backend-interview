# NoSQL, Redis и кэширование

## 1. Какие основные типы NoSQL-баз существуют?

NoSQL объединяет несколько разных моделей хранения. Key-value базы хранят значение по ключу и подходят для быстрых lookup и кэша. Документные базы хранят документы со структурой вроде JSON и удобны для гибкой схемы. Column-family системы оптимизированы под большие распределённые наборы данных и запросы по ключам/диапазонам. Графовые БД хранят вершины и связи и удобны там, где основная ценность — отношения между сущностями.

---

## 2. Для чего используют Redis?

Redis — in-memory хранилище структур данных. Его часто используют как кэш, хранилище сессий, счётчиков, rate limiting, распределённых блокировок, временных данных и для простых очередей/публикации событий. Он поддерживает не только строки, но и hash, list, set, sorted set и другие структуры. Поскольку данные в основном обслуживаются из памяти, Redis даёт очень низкую задержку, но схему сохранности и объём памяти нужно проектировать отдельно.

---

## 3. Что такое кэш?

Кэш — более быстрое промежуточное хранилище результатов, которые дорого получать повторно. При cache-aside приложение сначала проверяет кэш, при промахе читает основной источник и сохраняет результат в кэш. Главная сложность — не само чтение, а актуальность данных: нужно определить TTL, стратегию инвалидирования, поведение при промахе и ситуацию, когда кэш недоступен.

---

## 4. Чем SQL и NoSQL отличаются по подходу?

Реляционные БД используют таблицы, связи, строгую схему и мощный SQL; они хорошо подходят для данных с выраженными отношениями и транзакционными требованиями. NoSQL-системы часто выбирают более специализированную модель данных и проще масштабируют конкретный тип нагрузки, но обычно требуют проектировать запросы и консистентность под выбранное хранилище. Выбор делается по модели данных и нагрузке, а не по принципу «NoSQL быстрее SQL».
