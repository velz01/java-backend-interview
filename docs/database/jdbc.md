# JDBC

JDBC API, соединения, запросы, ResultSet и транзакции.

## 1. Что такое JDBC?

JDBC (Java Database Connectivity) — стандартный Java API для взаимодействия с реляционными СУБД. Он определён главным образом в пакетах java.sql и javax.sql и опирается на JDBC-драйвер конкретной базы. Приложение работает с едиными интерфейсами Connection, Statement, ResultSet и другими, а драйвер преобразует эти вызовы в протокол конкретной СУБД.

## 2. В чём преимущества JDBC?

JDBC отделяет Java-код от низкоуровневого протокола конкретной базы и задаёт единый API. При смене СУБД основная модель работы с соединением и результатами остаётся прежней, хотя SQL-диалект и специфические возможности могут потребовать изменений. Подключение описывается через JDBC URL и драйвер.

## 3. Что такое JDBC URL?

JDBC URL начинается с jdbc:, затем содержит подпротокол/идентификатор драйвера и специфичную для него часть адреса. Например, URL PostgreSQL обычно содержит host, port и database. Формат оставшейся части задаёт конкретный драйвер и может включать дополнительные параметры соединения.

## 4. Из каких частей состоит JDBC?

Условно JDBC состоит из API и драйвера. API — набор стандартных интерфейсов и классов Java, описывающих соединение, запросы, результаты и транзакции. JDBC-драйвер реализует этот контракт для конкретной СУБД и преобразует вызовы API в её сетевой протокол.

## 5. Какие основные классы и интерфейсы JDBC нужно знать?

DriverManager и DataSource используются для получения соединений. Connection представляет соединение и управляет транзакциями. Statement, PreparedStatement и CallableStatement отправляют запросы. ResultSet содержит результат SELECT и позволяет перемещаться по строкам. ResultSetMetaData и DatabaseMetaData дают метаинформацию. В серверных приложениях обычно предпочитают DataSource и пул соединений.

## 6. Как выглядит типичный алгоритм работы с JDBC?

Получить Connection, создать Statement/PreparedStatement, задать параметры, выполнить executeQuery/executeUpdate, обработать ResultSet или количество изменённых строк и корректно закрыть ресурсы. На практике Connection, Statement и ResultSet удобно закрывать через try-with-resources. Для нескольких связанных изменений отдельно управляют транзакцией: отключают autoCommit, выполняют операции и вызывают commit либо rollback.

## 7. Как JDBC связывает SQL-типы с Java-типами?

ResultSet и PreparedStatement предоставляют типизированные методы: getInt/setInt, getString/setString, getBigDecimal/setBigDecimal, getDate/setDate и т.д. JDBC также определяет java.sql.Types. Нужно учитывать nullable-значения и различия между SQL DATE/TIME/TIMESTAMP и современным java.time API, который поддерживается современными JDBC-драйверами.

## 8. Как зарегистрировать JDBC-драйвер?

Исторически драйвер явно загружали через Class.forName(), после чего он регистрировался в DriverManager. Начиная с JDBC 4 драйверы обычно обнаруживаются автоматически через механизм сервис-провайдеров, если JAR драйвера находится в classpath. Явная регистрация для современных драйверов обычно не требуется.

## 9. Как установить соединение с базой данных?

Можно использовать DriverManager.getConnection(url, user, password), но в приложениях чаще используется DataSource, часто предоставляемый пулом соединений. Полученный Connection — дорогой ресурс, поэтому серверные приложения обычно не создают новое физическое TCP-соединение на каждый запрос, а арендуют готовое из пула.

## 10. Какие уровни изоляции поддерживает JDBC?

Connection определяет константы TRANSACTION_READ_UNCOMMITTED, TRANSACTION_READ_COMMITTED, TRANSACTION_REPEATABLE_READ и TRANSACTION_SERIALIZABLE, а также TRANSACTION_NONE. Текущий уровень можно узнать через getTransactionIsolation() и изменить через setTransactionIsolation(), если драйвер и СУБД это поддерживают.

## 11. При помощи чего формируются запросы в JDBC?

Основные варианты — Statement, PreparedStatement и CallableStatement. Statement подходит для заранее сформированного SQL без параметров. PreparedStatement содержит параметризованный запрос и позволяет безопасно передавать значения. CallableStatement предназначен для вызова хранимых процедур и функций.

## 12. Чем Statement отличается от PreparedStatement?

PreparedStatement создаётся из SQL с placeholders '?', а значения передаются отдельными set-методами. Это отделяет данные от SQL-кода, снижает риск SQL injection и позволяет драйверу/СУБД повторно использовать подготовленный план там, где это поддерживается. Statement работает с готовой строкой SQL и чаще подходит для простых одноразовых команд без пользовательских параметров.

## 13. Как выполнить SELECT и обработать ResultSet?

Для SELECT обычно вызывают executeQuery(), получая ResultSet. Курсор сначала находится перед первой строкой; next() переводит его на следующую строку и возвращает false после конца данных. Значения читают по имени или индексу столбца через getString(), getLong() и другие методы. Ресурс нужно закрыть вместе со Statement и Connection.

## 14. Как вызвать хранимую процедуру?

Используют Connection.prepareCall() и CallableStatement. В строке задаётся JDBC call syntax, затем устанавливаются входные параметры, регистрируются OUT-параметры, выполняется вызов и считываются результаты. Конкретная форма вызова и поддержка процедур зависят от СУБД.

## 15. Как правильно закрывать JDBC-ресурсы?

Connection, Statement и ResultSet реализуют AutoCloseable, поэтому основной способ — try-with-resources. Закрывать их важно всегда, включая ветки с исключениями. Если используется пул, close() на Connection обычно не закрывает физическое соединение, а возвращает его в пул.
