## 1. Что такое объектно-ориентированное программирование (ООП)?

__Объектно-ориентированное программирование (ООП)__ — методология программирования, основанная на представлении программы в виде совокупности объектов, каждый из которых является экземпляром определенного класса, а классы образуют иерархию наследования. 

+ объектно-ориентированное программирование использует в качестве основных логических конструктивных элементов объекты, а не алгоритмы;
+ каждый объект является экземпляром определенного класса 
+ классы образуют иерархии. 

Программа считается объектно-ориентированной, только если выполнены все три указанных требования. В частности, программирование, не использующее наследование, называется не объектно-ориентированным, а программированием с помощью абстрактных типов данных.

Согласно парадигме ООП программа состоит из объектов, обменивающихся сообщениями. Объекты могут обладать состоянием, единственный способ изменить состояние объекта - послать ему сообщение, в ответ на которое, объект может изменить собственное состояние.

## 2. Расскажите подробнее про основные понятия ООП: _«класс»_, _«объект»_, _«интерфейс»_.

__Класс__ – это способ описания сущности, определяющий состояние и поведение, зависящее от этого состояния, а также правила для взаимодействия с данной сущностью (контракт). 

С точки зрения программирования класс можно рассматривать как набор данных (полей, атрибутов, членов класса) и функций для работы с ними (методов).

С точки зрения структуры программы, класс является сложным типом данных.

__Объект (экземпляр)__ – это отдельный представитель класса, имеющий конкретное состояние и поведение, полностью определяемое классом. Каждый объект имеет конкретные значения атрибутов и методы, работающие с этими значениями на основе правил, заданных в классе.

__Интерфейс__ – это набор методов класса, доступных для использования. Интерфейсом класса будет являться набор всех его публичных методов в совокупности с набором публичных атрибутов. По сути, интерфейс специфицирует класс, чётко определяя все возможные действия над ним.

## 3. Что такое инкапсуляция?

Инкапсуляция — это сокрытие внутренних свойств и логики поведения объекта от пользователя. Под пользователем здесь понимается другой код, который работает с объектом.

Для работы с объектом предоставляются публичные методы, а данные и вспомогательные действия скрываются через `private`.

```java
class Phone {
    private boolean connected;

    private void connect() {
        connected = true;
        System.out.println("Соединение установлено");
    }

    public void call() {
        connect();
        System.out.println("Вызов абонента");
    }
}
```

Другой код вызывает `call()`, а телефон сам устанавливает соединение и начинает вызов. Напрямую изменить поле `connected` или вызвать `connect()` извне класса нельзя.

Внутреннюю логику соединения можно изменить, сохранив публичный метод `call()`. Код, который пользуется телефоном, продолжит работать прежним способом.

## 4. Что такое наследование?

Наследование позволяет создать класс на основе другого класса. Наследник получает доступные поля и методы родителя, может добавлять свои и переопределять поведение.

В Java для наследования классов используется `extends`.

```java
class Animal {
    public void eat() {
        System.out.println("Ест");
    }
}

class Dog extends Animal {
    public void bark() {
        System.out.println("Гав");
    }
}
```

У объекта `Dog` есть унаследованный метод `eat()` и собственный метод `bark()`.

Класс может наследоваться только от одного класса.

## 5. Что такое полиморфизм? Как он реализуется в Java?

Полиморфизм позволяет работать с объектами разных классов через общий родительский тип или интерфейс.

В Java обычно выделяют **статический** и **динамический** полиморфизм.

**Статический полиморфизм — перегрузка методов**

Несколько методов имеют одинаковое имя, но разные параметры. Компилятор заранее определяет, какой метод вызвать, исходя из количества аргументов и их типов.

```java
class Printer {
    public void print(String value) {
        System.out.println("Строка: " + value);
    }

    public void print(int value) {
        System.out.println("Число: " + value);
    }
}
```

Использование:

```java
Printer printer = new Printer();
printer.print("Привет"); // Компилятор выбирает print(String)
printer.print(10);       // Компилятор выбирает print(int)
```

Выбор происходит **при компиляции**, поэтому полиморфизм называют статическим. Самим методам модификатор `static` не нужен.

**Динамический полиморфизм — переопределение методов**

Объекты разных классов используются через общий родительский тип или интерфейс. Конкретная реализация переопределённого метода выбирается **во время выполнения**, исходя из фактического класса объекта.

```java
class Animal {
    public void sound() {
        System.out.println("Звук");
    }
}

class Dog extends Animal {
    @Override
    public void sound() {
        System.out.println("Гав");
    }
}
```

Использование:

```java
Animal animal = new Dog();
animal.sound(); // Гав
```

Переменная имеет тип `Animal`, но хранит объект `Dog`, поэтому выполняется `Dog.sound()`.

| Вид | Реализация | Когда выбирается метод |
|---|---|---|
| Статический | Перегрузка: одинаковое имя, разные параметры | При компиляции |
| Динамический | Переопределение: своя реализация у наследника | Во время выполнения |

## 6. Что такое абстракция?

Абстракция — выделение важных для задачи свойств и действий объекта без подробностей его устройства.

Например, для оформления заказа важно уметь принять оплату. Конкретный способ оплаты можно скрыть за общим интерфейсом:

```java
interface Payment {
    void pay(int amount);
}

class Checkout {
    public void purchase(Payment payment) {
        payment.pay(100);
    }
}
```

`Checkout` знает, что у способа оплаты есть действие `pay()`. Ему не нужно знать, как именно проходит платёж — картой или банковским переводом.

Абстракция помогает определить, **что объект умеет делать**, а инкапсуляция — **как ограничить доступ к его внутренней реализации**.

## 7. Чем отличаются ассоциация, агрегация и композиция?

- **Ассоциация** — объекты связаны друг с другом. Например, студент учится у преподавателя.
- **Агрегация** — один объект входит в состав другого, но может существовать отдельно. Например, игрок входит в команду, но при расформировании команды игрок остаётся.
- **Композиция** — один объект является частью другого и без него не существует в этой модели. Например, позиция заказа принадлежит заказу: при удалении заказа удаляются и его позиции.

Агрегация и композиция — виды ассоциации. Главное различие между ними: **при агрегации часть самостоятельна, при композиции зависит от целого**.
