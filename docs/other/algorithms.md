# Алгоритмическая сложность

## Что такое Big O?

Асимптотическая верхняя оценка роста затрат алгоритма при увеличении входа. На интервью обычно говорят про time и space complexity и игнорируют constant factors для анализа роста.

## O(1), O(log n), O(n), O(n log n), O(n²)

- O(1) — доступ к элементу массива по индексу;
- O(log n) — поиск в сбалансированном дереве;
- O(n) — линейный проход;
- O(n log n) — типичная хорошая comparison sort;
- O(n²) — двойной полный вложенный цикл.

## Амортизированная сложность

Отдельная операция может быть дорогой, но средняя цена последовательности операций остаётся небольшой. Пример: `ArrayList.add` обычно O(1), иногда resize+copy O(n), поэтому append считается amortized O(1).

## Почему HashMap average O(1), а не гарантированно?

Из-за коллизий: если много ключей попало в один bucket, поиск выполняет дополнительную работу внутри bucket. Хорошая hash distribution делает такой сценарий редким.
