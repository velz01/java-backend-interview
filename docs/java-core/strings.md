# String, String Pool и строки

::: tip Приоритет
🔴 **Часто спрашивают.**
:::

## Почему String immutable?

### Короткий ответ
Содержимое String после создания не меняется. Операции возвращают новый String. Это позволяет безопасно использовать String Pool, hash-кэширование, keys и совместное чтение из разных потоков.

## Что такое String Pool?

### Короткий ответ
Пул канонических строковых литералов. Одинаковые compile-time literals могут ссылаться на один объект.

```java
String a = "java";
String b = "java";
String c = new String("java");

a == b; // true
a == c; // false
```

## Что делает intern()?

### Короткий ответ
Возвращает каноническое представление строки из pool. Использовать его как «оптимизацию всего подряд» не стоит: сначала нужна реальная причина и измерения.

## StringBuilder vs StringBuffer

### Короткий ответ
Оба mutable. `StringBuffer` синхронизирован, `StringBuilder` нет и обычно используется в обычном однопоточном коде.

## Почему `+=` в большом цикле может быть дорогим?

### Короткий ответ
String immutable, поэтому повторная конкатенация может создавать промежуточные объекты и копировать данные. Для большого числа append лучше StringBuilder.

## Что происходит с `"a" + "b"`?

### Короткий ответ
Если всё известно на compile-time, compiler может свернуть выражение в `"ab"`. При runtime values используется механизм динамической конкатенации.

## Почему char[] исторически предпочитали для паролей?

### Короткий ответ
Массив можно явно затереть, а immutable String остаётся в памяти до GC. Это не решает все security-проблемы, но показывает отличие mutable/immutable данных.
