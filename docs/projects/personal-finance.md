# Проект 1. Учёт личных финансов

В этом проекте напишем консольное приложение для учёта личных финансов. Пользователь сможет добавлять доходы и расходы, выбирать категории, смотреть историю операций и узнавать, сколько денег осталось.

## Цель проекта

Основная цель — самостоятельно написать небольшое приложение на Java и разобраться, как связать между собой классы, коллекции и ввод пользователя. Здесь будем практиковать то, что ты уже изучил в материалах перед проектом.

## Технологии и инструменты

- **Java** — используем стандартную библиотеку. Сторонние библиотеки и фреймворки здесь не нужны, конкретная версия Java не важна.
- **IntelliJ IDEA** — здесь пишем, запускаем и отлаживаем программу.
- **Git** — сохраняем изменения в коммитах. **GitHub** — выкладываем проект, чтобы отправить его на ревью.

## Функционал приложения

### Главное меню

```text
1. Добавить доход
2. Добавить расход
3. Показать историю операций
4. Удалить операцию
5. Категории расходов
6. Показать сводку
0. Выйти
```

После каждого действия снова показывай меню. Если пользователь ввёл неизвестную команду, сообщи об этом и предложи выбрать ещё раз. Команда «Выйти» завершает программу.

### Категории расходов

Начальные категории: «Продукты», «Транспорт», «Развлечения», «Другое».

Пользователь может посмотреть список категорий и добавить свою. У каждой категории есть название и ID, который программа назначает сама. ID категорий не должны повторяться. Категории и операции нумеруются отдельно.

Убирай пробелы по краям названия и проверяй, что оно не пустое. Одинаковые названия добавлять нельзя: «Еда» и «еда» считаются одной категорией. Удалять и переименовывать категории в этом проекте не нужно.

### Добавление дохода и расхода

У каждой операции есть ID, тип (доход или расход), сумма и описание. Для расхода также нужна категория из существующего списка. У дохода категории нет.

Пользователь вводит сумму и описание, а для расхода выбирает категорию из списка.

- Сумма — положительное целое число рублей, тип long. Работаем без копеек.
- Ноль, отрицательные и дробные значения, нечисловой ввод и числа вне диапазона long не принимаются.
- Описание после удаления пробелов по краям не должно быть пустым.
- Доходы и расходы нумеруются вместе, начиная с 1. Программа назначает ID автоматически.
- Если пользователь ошибся, попроси заново ввести только то значение, в котором ошибка.
- Добавляй операцию только после того, как пользователь правильно ввёл все данные.

```text
Введите сумму: 500
Категории:
1. Продукты
2. Транспорт
3. Развлечения
4. Другое

Введите ID категории: 1
Введите описание: Покупки к ужину
Расход добавлен. ID: 1
```

В примере это первая операция после запуска, поэтому её ID — 1. Сам диалог можно оформить по-своему, номера категорий тоже могут отличаться. Главное — показать список и дать выбрать категорию по ID.

### История операций

Добавь выбор: показать все операции, только доходы, только расходы или расходы выбранной категории. Совмещать несколько фильтров не нужно.

Показывай записи в порядке добавления: ID, тип, сумма, описание, категория при её наличии. Если записей нет, выводи понятное сообщение.

### Удаление операции

Попроси пользователя ввести ID операции. Если такая операция есть — удали её. Если ID не найден или вместо числа введён текст — сообщи об этом. После этого вернись в меню.

После удаления не меняй ID остальных операций. Новым операциям не выдавай удалённые номера до завершения программы.

### Финансовая сводка

Покажи сумму доходов, сумму расходов и баланс: доходы минус расходы. Ниже выведи, сколько потрачено в каждой категории. Категории без расходов показывать не нужно, порядок остальных может быть любым.

```text
Доходы: 10000 руб.
Расходы: 2300 руб.
Баланс: 7700 руб.

Расходы по категориям:
Продукты: 2000 руб.
Транспорт: 300 руб.
```

Если операций пока нет, все суммы равны нулю. Баланс может быть отрицательным — это нормально, когда расходы больше доходов. Считаем, что итоговые суммы помещаются в `long`, проверять переполнение при подсчёте не нужно.

## Хранение данных

Храни операции и категории в памяти программы. После закрытия данные пропадают. При новом запуске история пустая, категории снова начальные, а нумерация операций начинается с 1.

## Требования к организации кода

- Для операций и категорий создай классы, а для типа операции используй `enum`.
- Поля классов сделай `private`.
- Раздели код, который общается с пользователем, и код, который работает с данными. Хранение и расчёты не должны читать ввод или печатать сообщения. Например, метод подсчёта баланса должен вернуть сумму, а вывести её в консоль нужно уже в другом месте.
- Каждый метод должен решать одну задачу.
- Храни доходы и расходы в одной коллекции операций.
- Для подсчёта расходов по категориям используй `Map`.
- Для повторного показа меню используй цикл. Не вызывай метод меню из него самого.
- Не храни все данные в полях `public static`.

Какие классы нужны и за что они будут отвечать — продумай сам. Наследование и интерфейсы здесь необязательны. Важно, чтобы ты понимал, зачем нужен каждый класс, какие данные он хранит и как работает с остальными.

По мере работы отделяй ввод и вывод от хранения данных и расчётов. ООП к этому моменту уже должно быть знакомо по материалам — здесь пробуем применять его в своём коде.

Проверки ввода добавляй сразу вместе с функцией, чтобы потом не переделывать всё приложение. После каждого этапа делай коммит с работающей версией.

## Чек-лист самопроверки

Перед сдачей пройди по списку и проверь каждый пункт в запущенной программе.

### Меню и запуск

- Можно выполнить несколько действий подряд: после каждого приложение возвращается в меню.
- Неизвестная команда вызывает понятное сообщение; меню появляется снова.
- Команда выхода завершает программу.
- После перезапуска история пуста, доступны начальные категории, нумерация операций начинается с 1.

### Операции и категории

- Доходы и расходы получают уникальные ID из общей последовательности. В истории видны все данные операции, записи идут в порядке добавления.
- Суммы `0`, `-100`, `1.5`, `abc` и `9223372036854775808` не принимаются. Последнее число выходит за диапазон `long`. Программа повторно запрашивает сумму и продолжает работу.
- Пустое описание и описание из одних пробелов не принимаются. Пробелы по краям корректного описания убираются.
- Пока все данные операции не введены корректно, она не появляется в истории и не влияет на сводку.
- Новая категория появляется в списке с собственным ID и доступна для выбора при добавлении расхода.
- Пустое название категории и название из одних пробелов не принимаются. После создания «Еда» названия «еда» и « Еда » не создают новые категории.
- Нельзя добавить расход с неизвестным ID категории. У дохода категории нет.

### История и удаление

- Пустая история показывает понятное сообщение.
- Фильтры показывают все операции, только доходы, только расходы или расходы выбранной категории — в зависимости от выбора.
- Если подходящих записей нет, фильтр показывает понятное сообщение.
- Удалённая операция исчезает из истории. ID оставшихся записей не меняются, а новая операция не получает удалённый ID.
- При удалении неизвестный ID и нечисловой ввод вызывают сообщение и возврат в меню; история не меняется.

### Сводка

- Без операций доходы, расходы и баланс равны нулю.
- Доходы, расходы и баланс совпадают с контрольным примером ниже.
- Удаление дохода уменьшает общие доходы и баланс; удаление расхода уменьшает общие расходы и увеличивает баланс.
- Если расходы превышают доходы, баланс отрицательный.
- Расходы по категориям подсчитаны верно. Категории без расходов не выводятся, в том числе после удаления последнего расхода категории.

Контрольный пример: добавь доход 10000, расходы 1500 и 500 в «Продукты», расход 300 в «Транспорт». Доходы — 10000, расходы — 2300, баланс — 7700. По категориям: продукты — 2000, транспорт — 300. Удали расход 500: расходы — 1800, баланс — 8200, продукты — 1500.
