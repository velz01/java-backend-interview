# ООП и базовые конструкции

::: tip Приоритет
🔴 **Обязательно знать.** Лучше приводить короткий пример из обычного backend-кода, а не давать только академическое определение.
:::

## Какие четыре принципа ООП?

### Короткий ответ
**Инкапсуляция** скрывает детали реализации и даёт контролируемый API. **Наследование** позволяет переиспользовать и специализировать поведение. **Полиморфизм** позволяет работать через общий контракт с разными реализациями. **Абстракция** оставляет в модели только важные для задачи свойства и действия.

### Подробнее
Хороший ответ связывает принципы с практикой. Например, поле `balance` не должно свободно меняться снаружи: метод `withdraw()` проверяет правила — это инкапсуляция. Интерфейс `PaymentGateway` с несколькими реализациями показывает полиморфизм. Наследование стоит применять осторожно: если между классами нет настоящего отношения «is-a», композиция обычно безопаснее.

## Interface vs abstract class

### Короткий ответ
Интерфейс задаёт контракт и позволяет классу реализовать несколько контрактов. Абстрактный класс подходит, когда у родственных классов есть общее состояние, конструктор и часть общей реализации.

### Подробнее
Современный интерфейс может содержать `default`, `static` и `private` методы, но общего mutable-state экземпляров у него нет как у класса. Если нужно несколько независимых «ролей» — чаще интерфейс. Если нужна общая база для близких сущностей — возможен abstract class.

## Overloading vs overriding

### Короткий ответ
**Overloading** — одно имя метода, разные параметры; выбор происходит на этапе компиляции. **Overriding** — наследник переопределяет метод родителя/интерфейса; нужная реализация выбирается во время выполнения.

### Ловушки
- Нельзя перегрузить метод только изменением return type.
- При override нельзя уменьшать visibility.
- Checked exception в override нельзя расширить по отношению к родительскому методу.

## Что делает final?

### Короткий ответ
Для переменной — запрещает переназначение после инициализации, для метода — override, для класса — наследование.

::: warning
`final List<String> list` не делает сам список immutable. Нельзя поменять ссылку, но содержимое списка всё ещё можно менять.
:::

## Что такое immutable object?

### Короткий ответ
Объект, чьё наблюдаемое состояние не меняется после создания. Обычно поля `private final`, нет setters, а mutable вложенные объекты копируются при входе/выходе.

### Зачем
Immutable-объекты проще использовать как keys, передавать между потоками и кэшировать: их состояние не меняется неожиданно.
